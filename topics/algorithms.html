فرایند حل مسئله و تحلیل Big-O، همراه با الگوهای پرکاربرد (Hash Map، Two Pointers، Sliding Window، Prefix Sum، Stack، Binary Search)، مرتب‌سازی، درخت، Heap، گراف، Greedy و برنامه‌نویسی پویا؛ همه با پیاده‌سازی PHP و مسائل کلاسیک مصاحبه‌ای.

فرایند حل مسئله

در آزمون تشریحی یا مصاحبه، فرایند فکر کردن به اندازه‌ی جواب نهایی نمره دارد. یک چارچوب شش‌مرحله‌ای:

  1. درک مسئله: ورودی و خروجی دقیقاً چیست؟ محدودیت‌ها (اندازه‌ی n، بازه‌ی مقادیر، منفی/تکراری، مرتب بودن)؟ سوال را با کلمات خودتان بازنویسی کنید.
  2. مثال‌ها: یک مثال عادی، یک مثال کوچک و حالت‌های مرزی (آرایه‌ی خالی، یک عنصر، همه یکسان، اعداد منفی، خیلی بزرگ).
  3. راه‌حل Brute Force: ساده‌ترین راه درست را بگویید و پیچیدگی‌اش را تحلیل کنید. این نقطه‌ی شروع مطمئن است.
  4. بهینه‌سازی: گلوگاه کجاست؟ کار تکراری؟ آیا ساختار داده‌ای (hash map، heap) یا الگویی (two pointers، sorting، binary search، DP) کمک می‌کند؟ معاوضه‌ی حافظه با زمان.
  5. پیاده‌سازی: کد تمیز با نام‌گذاری روشن، توابع کمکی، و رسیدگی به حالت‌های مرزی.
  6. تست و تحلیل: کد را روی مثال‌ها دستی اجرا کنید (dry run)، حالت‌های مرزی را چک کنید و پیچیدگی زمانی و حافظه‌ی نهایی را بیان کنید.

Big-O: پیچیدگی زمانی و حافظه

قواعد محاسبه

  • حلقه‌های پشت سر هم جمع می‌شوند: O(n) + O(m) = O(n + m).
  • حلقه‌های تودرتو ضرب می‌شوند: O(n × m).
  • نصف کردن مداوم فضای مسئله ⇒ log n.
  • بازگشت با دو شاخه و عمق n ⇒ حدود O(2ⁿ)؛ تقسیم به دو نیمه + کار خطی در هر سطح ⇒ O(n log n) (Master Theorem).
  • ورودی‌های مستقل را با متغیرهای جدا بنویسید (O(V + E)، O(m × n)).

آرایه، رشته و Hash Map

آرایه

  • آرایه‌ی کلاسیک: بلوک پیوسته‌ی حافظه؛ دسترسی با اندیس O(1)، درج/حذف در وسط O(n) (جابه‌جایی عناصر).
  • Dynamic Array (مثل vector یا ArrayList): وقتی پر شد، ظرفیت را (معمولاً) دو برابر و عناصر را کپی می‌کند؛ هزینه‌ی append به‌صورت amortized O(1).
  • در PHP، array در واقع hash table مرتب است (کلید عددی یا رشته‌ای). برای آرایه‌ی «packed» با کلیدهای ۰..n-1 بهینه‌سازی دارد، ولی مفهوماً map است. SplFixedArray آرایه‌ی واقعی با اندازه‌ی ثابت است.

Hash Map و Hash Set

Hash table با یک تابع hash کلید را به اندیس یک bucket نگاشت می‌کند؛ درج، حذف و جست‌وجو به‌طور میانگین O(1) و در بدترین حالت (برخورد زیاد) O(n) است.

key "apple" ──hash()──► 3      buckets:
key "melon" ──hash()──► 3      [0] → ∅
key "kiwi"  ──hash()──► 0      [1] → ∅
                               [2] → ∅
                               [3] → ("apple",5) → ("melon",2)   ◄── collision (chaining)

رسیدگی به برخورد (Collision)

  • Separate Chaining: هر bucket یک لیست (یا درخت) از عناصر دارد. ساده؛ با load factor بالا هم کار می‌کند. (پیاده‌سازی hash table در PHP از این نوع است.)
  • Open Addressing: همه‌ی عناصر در خود آرایه؛ در برخورد، خانه‌ی بعدی با Linear Probing، Quadratic Probing یا Double Hashing جست‌وجو می‌شود. cache-friendly ولی حساس به load factor و حذف (نیاز به tombstone).
  • Load Factor = تعداد عناصر / تعداد bucketها. وقتی از آستانه گذشت، جدول بزرگ‌تر و همه‌ی کلیدها rehash می‌شوند (O(n) ولی amortized O(1)).

Hash Flooding: اگر مهاجم بتواند کلیدهایی بسازد که همه در یک bucket بیفتند، هر عملیات O(n) و کل پردازش O(n²) می‌شود (حمله‌ی DoS). یکی از دلایل وجود تنظیم max_input_vars در PHP همین است. hash تصادفی‌شده (seeded) راه‌حل رایج زبان‌هاست.

نکته‌ی PHP: کلیدهای رشته‌ای که عدد صحیح دهدهی معتبرند به int تبدیل می‌شوند ("42" → 42)، و کلید float به int بریده می‌شود. برای set از $set[$x] = true و isset($set[$x]) استفاده کنید، نه in_array. array_flip آرایه‌ی مقادیر را در O(n) به set تبدیل می‌کند.

<?php
// شمارش فراوانی کلمات — O(n)
function wordFrequency(string $text): array
{
    $freq = [];
    foreach (preg_split('/\s+/u', mb_strtolower(trim($text)), -1, PREG_SPLIT_NO_EMPTY) as $w) {
        $freq[$w] = ($freq[$w] ?? 0) + 1;
    }
    arsort($freq);           // مرتب‌سازی نزولی بر اساس مقدار
    return $freq;
}

// اولین کاراکتر غیرتکراری — دو گذر O(n)
function firstUniqueChar(string $s): int
{
    $count = count_chars($s, 1);              // byte => تعداد
    for ($i = 0, $n = strlen($s); $i < $n; $i++) {
        if ($count[ord($s[$i])] === 1) return $i;
    }
    return -1;
}

رشته‌ها در PHP

  • رشته‌ی PHP آرایه‌ای از بایت است؛ $s[$i] و strlen بایت‌محورند. برای متن فارسی/UTF-8 از mb_strlen، mb_substr و mb_str_split استفاده کنید.
  • رشته‌ها copy-on-write هستند؛ ساختن رشته‌ی جدید در هر مرحله‌ی حلقه می‌تواند هزینه داشته باشد.

Two Pointers و Sliding Window

Two Pointers

دو اشاره‌گر که با هم یا در خلاف جهت حرکت می‌کنند و با استفاده از ساختار داده (معمولاً مرتب بودن) فضای جست‌وجو را در هر گام کوچک می‌کنند؛ O(n²) را به O(n) می‌رساند.

<?php
// جفت با مجموع target در آرایه‌ی مرتب — O(n) زمان، O(1) حافظه
function pairSumSorted(array $a, int $target): ?array
{
    $l = 0;
    $r = count($a) - 1;
    while ($l < $r) {
        $sum = $a[$l] + $a[$r];
        if ($sum === $target) return [$l, $r];
        if ($sum < $target) $l++;   // نیاز به مجموع بزرگ‌تر
        else $r--;                    // نیاز به مجموع کوچک‌تر
    }
    return null;
}

// پالیندروم با نادیده گرفتن غیرحروف
function isPalindrome(string $s): bool
{
    $s = strtolower(preg_replace('/[^a-z0-9]/i', '', $s));
    for ($l = 0, $r = strlen($s) - 1; $l < $r; $l++, $r--) {
        if ($s[$l] !== $s[$r]) return false;
    }
    return true;
}

// حذف تکراری‌ها از آرایه‌ی مرتب در جا (slow/fast pointers)
function removeDuplicates(array &$a): int
{
    if ($a === []) return 0;
    $slow = 0;
    for ($fast = 1, $n = count($a); $fast < $n; $fast++) {
        if ($a[$fast] !== $a[$slow]) {
            $a[++$slow] = $a[$fast];
        }
    }
    return $slow + 1;   // طول بخش یکتا
}

Sliding Window

برای مسائل «زیرآرایه/زیررشته‌ی پیوسته» یک پنجره [left, right] نگه می‌داریم؛ right را جلو می‌بریم و هر وقت پنجره نامعتبر شد left را جلو می‌بریم. هر عنصر حداکثر یک بار وارد و یک بار خارج می‌شود ⇒ O(n).

<?php
// پنجره‌ی ثابت: بیشترین مجموع k عنصر متوالی — O(n)
function maxSumWindow(array $a, int $k): int
{
    $sum = array_sum(array_slice($a, 0, $k));
    $best = $sum;
    for ($i = $k, $n = count($a); $i < $n; $i++) {
        $sum += $a[$i] - $a[$i - $k];   // ورود یکی، خروج یکی
        $best = max($best, $sum);
    }
    return $best;
}

// پنجره‌ی متغیر: کوتاه‌ترین زیرآرایه با مجموع >= target (اعداد مثبت)
function minSubArrayLen(int $target, array $a): int
{
    $left = 0; $sum = 0; $best = PHP_INT_MAX;
    foreach ($a as $right => $x) {
        $sum += $x;
        while ($sum >= $target) {               // تا وقتی معتبر است، کوچکش کن
            $best = min($best, $right - $left + 1);
            $sum -= $a[$left++];
        }
    }
    return $best === PHP_INT_MAX ? 0 : $best;
}

Sliding window با مجموع فقط وقتی درست کار می‌کند که اعداد نامنفی باشند (افزودن عنصر مجموع را کم نکند). با اعداد منفی از Prefix Sum + Hash Map استفاده کنید.

Prefix Sum

آرایه‌ی prefix[i] = مجموع a[0..i-1]. با یک پیش‌پردازش O(n)، مجموع هر بازه در O(1): sum(l..r) = prefix[r+1] - prefix[l].

a      =    [ 3,  1,  4,  1,  5 ]
prefix = [ 0, 3,  4,  8,  9, 14 ]
sum(1..3) = prefix[4] - prefix[1] = 9 - 3 = 6   (1 + 4 + 1)
<?php
final class RangeSum
{
    private array $prefix = [0];

    public function __construct(array $a)
    {
        foreach ($a as $i => $x) {
            $this->prefix[$i + 1] = $this->prefix[$i] + $x;
        }
    }

    public function sum(int $l, int $r): int      // شامل هر دو سر
    {
        return $this->prefix[$r + 1] - $this->prefix[$l];
    }
}

// تعداد زیرآرایه‌های پیوسته با مجموع k (اعداد منفی هم مجازند) — O(n)
function subarraySum(array $a, int $k): int
{
    $seen = [0 => 1];        // prefix sum => چند بار دیده شده
    $sum = 0; $count = 0;
    foreach ($a as $x) {
        $sum += $x;
        $count += $seen[$sum - $k] ?? 0;   // prefix قبلی که فاصله‌اش k است
        $seen[$sum] = ($seen[$sum] ?? 0) + 1;
    }
    return $count;
}

کاربرد واقعی: گزارش «جمع فروش بین دو تاریخ» روی داده‌ی تجمعی روزانه، یا جدول‌های cumulative در دیتابیس. نسخه‌ی دوبعدی هم برای مجموع زیرماتریس وجود دارد.

Stack، Queue و Monotonic Stack

Stack (LIFO)

  • push / pop / peek در O(1).
  • کاربرد: call stack، undo، پرانتزگذاری، DFS تکراری، ارزیابی عبارت.
  • PHP: آرایه با $s[] = $x و array_pop، یا SplStack.

Queue (FIFO)

  • enqueue / dequeue در O(1).
  • کاربرد: BFS، صف کارها (Laravel Queue)، buffer، rate limiting.
  • PHP: SplQueue (لیست پیوندی دوطرفه). array_shift برای صف O(n) است.

Monotonic Stack

پشته‌ای که عناصرش همیشه به‌صورت یکنوا (صعودی یا نزولی) مرتب‌اند. برای مسائل «عنصر بزرگ‌تر/کوچک‌تر بعدی» در O(n) به جای O(n²). هر عنصر حداکثر یک بار push و یک بار pop می‌شود.

<?php
// Daily Temperatures: چند روز تا روز گرم‌تر؟ — O(n)
function dailyTemperatures(array $t): array
{
    $n = count($t);
    $answer = array_fill(0, $n, 0);
    $stack = [];                                   // اندیس‌ها؛ دما نزولی
    for ($i = 0; $i < $n; $i++) {
        while ($stack !== [] && $t[$i] > $t[end($stack)]) {
            $j = array_pop($stack);
            $answer[$j] = $i - $j;                 // روز i اولین روز گرم‌تر برای j است
        }
        $stack[] = $i;
    }
    return $answer;
}
// [73,74,75,71,69,72,76,73] → [1,1,4,2,1,1,0,0]

Monotonic Queue (deque یکنوا) هم برای «بیشینه‌ی هر پنجره‌ی لغزان به طول k» در O(n) کاربرد دارد.

<?php
final class ListNode
{
    public function __construct(
        public int $val,
        public ?ListNode $next = null,
    ) {}
}

// پیدا کردن گره میانی: fast دو قدم، slow یک قدم — O(n)
function middleNode(?ListNode $head): ?ListNode
{
    $slow = $fast = $head;
    while ($fast !== null && $fast->next !== null) {
        $slow = $slow->next;
        $fast = $fast->next->next;
    }
    return $slow;
}

// تشخیص حلقه (Floyd's Tortoise and Hare) — O(n) زمان، O(1) حافظه
function hasCycle(?ListNode $head): bool
{
    $slow = $fast = $head;
    while ($fast !== null && $fast->next !== null) {
        $slow = $slow->next;
        $fast = $fast->next->next;
        if ($slow === $fast) return true;     // مقایسه‌ی هویت شیء
    }
    return false;
}

// ادغام دو لیست مرتب با گره نگهبان (dummy)
function mergeTwoLists(?ListNode $a, ?ListNode $b): ?ListNode
{
    $dummy = new ListNode(0);
    $tail = $dummy;
    while ($a !== null && $b !== null) {
        if ($a->val <= $b->val) { $tail->next = $a; $a = $a->next; }
        else                     { $tail->next = $b; $b = $b->next; }
        $tail = $tail->next;
    }
    $tail->next = $a ?? $b;
    return $dummy->next;
}

ترفندهای linked list: dummy node برای حذف حالت خاص سر لیست، fast/slow pointers برای وسط و حلقه، و فاصله‌ی ثابت بین دو اشاره‌گر برای «k-امین گره از آخر».

بازگشت (Recursion)

تابعی که خودش را با ورودی کوچک‌تر صدا می‌زند. دو جزء ضروری:

  • Base case: شرط توقف؛ بدون آن بازگشت بی‌پایان و stack overflow.
  • Recursive case: کاهش مسئله به نمونه‌ی کوچک‌تر که به base case همگرا شود.
<?php
function factorial(int $n): int
{
    if ($n <= 1) return 1;            // base case
    return $n * factorial($n - 1);    // recursive case
}
// زمان O(n)، حافظه O(n) به خاطر call stack

// توان سریع: x^n با تقسیم و حل — O(log n)
function power(float $x, int $n): float
{
    if ($n === 0) return 1.0;
    if ($n < 0) return 1 / power($x, -$n);
    $half = power($x, intdiv($n, 2));
    return $n % 2 === 0 ? $half * $half : $half * $half * $x;
}

// Backtracking: همه‌ی زیرمجموعه‌ها — O(n · 2ⁿ)
function subsets(array $nums): array
{
    $result = [];
    $current = [];
    $dfs = function (int $start) use (&$dfs, &$result, &$current, $nums): void {
        $result[] = $current;
        for ($i = $start, $n = count($nums); $i < $n; $i++) {
            $current[] = $nums[$i];       // انتخاب
            $dfs($i + 1);                 // کاوش
            array_pop($current);          // برگرداندن انتخاب (backtrack)
        }
    };
    $dfs(0);
    return $result;
}

هر فراخوانی بازگشتی یک frame روی call stack می‌گذارد؛ پس حافظه‌ی بازگشت O(عمق) است. PHP بهینه‌سازی tail-call ندارد، و Xdebug هم محدودیت عمق فراخوانی دارد. برای عمق خیلی زیاد (لیست پیوندی میلیونی) نسخه‌ی تکراری با stack صریح بنویسید.

بازگشت در برابر تکرار: بازگشت برای ساختارهای بازگشتی (درخت، گراف، تقسیم و حل، backtracking) کد خواناتری می‌دهد؛ تکرار حافظه‌ی stack مصرف نمی‌کند و معمولاً سریع‌تر است. هر بازگشتی را می‌توان با stack صریح به تکرار تبدیل کرد.

Binary Search

در آرایه‌ی مرتب، با مقایسه‌ی عنصر وسط نیمی از فضای جست‌وجو را در هر گام حذف می‌کنیم ⇒ O(log n). شرط اصلی: یک خاصیت یکنوا (monotonic) که بازه را به «false…false true…true» تقسیم کند.

<?php
// نسخه‌ی کلاسیک: اندیس target یا -1
function binarySearch(array $a, int $target): int
{
    $lo = 0;
    $hi = count($a) - 1;
    while ($lo <= $hi) {
        $mid = $lo + intdiv($hi - $lo, 2);   // جلوگیری از overflow در زبان‌های با int محدود
        if ($a[$mid] === $target) return $mid;
        if ($a[$mid] < $target) $lo = $mid + 1;
        else $hi = $mid - 1;
    }
    return -1;
}

// lower bound: اولین اندیسی که a[i] >= x (یا count اگر نبود)
function lowerBound(array $a, int $x): int
{
    $lo = 0;
    $hi = count($a);                // بازه‌ی نیم‌باز [lo, hi)
    while ($lo < $hi) {
        $mid = $lo + intdiv($hi - $lo, 2);
        if ($a[$mid] < $x) $lo = $mid + 1;
        else $hi = $mid;
    }
    return $lo;
}
// اولین وقوع x:  $i = lowerBound($a, $x); return ($i < count($a) && $a[$i] === $x) ? $i : -1;
// تعداد وقوع x:  lowerBound($a, $x + 1) - lowerBound($a, $x)

اشکالات رایج: حلقه‌ی بی‌نهایت وقتی lo = mid و mid پایین گرد شود؛ ناسازگاری بازه‌ی بسته [lo, hi] با شرط lo < hi؛ off-by-one در مقدار اولیه‌ی hi. یک قرارداد (بسته یا نیم‌باز) انتخاب کنید و به آن پایبند بمانید.

Binary Search on Answer

وقتی جواب یک عدد در بازه‌ی [lo, hi] است و تابع «آیا با مقدار X ممکن است؟» یکنواست، روی خود جواب binary search می‌زنیم.

<?php
// حداقل ظرفیت کامیون برای ارسال همه‌ی بسته‌ها (به ترتیب) در days روز
function shipWithinDays(array $weights, int $days): int
{
    $lo = max($weights);            // حداقل: سنگین‌ترین بسته
    $hi = array_sum($weights);      // حداکثر: همه در یک روز
    while ($lo < $hi) {
        $cap = $lo + intdiv($hi - $lo, 2);
        if (canShip($weights, $days, $cap)) $hi = $cap;   // ممکن است → کمتر را امتحان کن
        else $lo = $cap + 1;
    }
    return $lo;
}

function canShip(array $weights, int $days, int $cap): bool
{
    $need = 1; $load = 0;
    foreach ($weights as $w) {
        if ($load + $w > $cap) { $need++; $load = 0; }
        $load += $w;
    }
    return $need <= $days;
}
// زمان: O(n · log(sum))

<?php
function mergeSort(array $a): array
{
    $n = count($a);
    if ($n <= 1) return $a;
    $mid = intdiv($n, 2);
    return mergeSorted(mergeSort(array_slice($a, 0, $mid)), mergeSort(array_slice($a, $mid)));
}

function mergeSorted(array $l, array $r): array
{
    $out = [];
    $i = $j = 0;
    $nl = count($l); $nr = count($r);
    while ($i < $nl && $j < $nr) {
        $out[] = $l[$i] <= $r[$j] ? $l[$i++] : $r[$j++];   // <= برای stable بودن
    }
    while ($i < $nl) $out[] = $l[$i++];
    while ($j < $nr) $out[] = $r[$j++];
    return $out;
}

Quick Sort (Lomuto partition)

<?php
function quickSort(array &$a, int $lo = 0, ?int $hi = null): void
{
    $hi ??= count($a) - 1;
    if ($lo >= $hi) return;
    $p = partition($a, $lo, $hi);
    quickSort($a, $lo, $p - 1);
    quickSort($a, $p + 1, $hi);
}

function partition(array &$a, int $lo, int $hi): int
{
    $r = random_int($lo, $hi);                       // pivot تصادفی: جلوگیری از بدترین حالت روی ورودی مرتب
    [$a[$r], $a[$hi]] = [$a[$hi], $a[$r]];
    $pivot = $a[$hi];
    $i = $lo;
    for ($j = $lo; $j < $hi; $j++) {
        if ($a[$j] < $pivot) {
            [$a[$i], $a[$j]] = [$a[$j], $a[$i]];
            $i++;
        }
    }
    [$a[$i], $a[$hi]] = [$a[$hi], $a[$i]];
    return $i;                                       // pivot در جای نهایی‌اش
}

<?php
final class TreeNode
{
    public function __construct(
        public int $val,
        public ?TreeNode $left = null,
        public ?TreeNode $right = null,
    ) {}
}

function inorder(?TreeNode $node, array &$out): void
{
    if ($node === null) return;
    inorder($node->left, $out);
    $out[] = $node->val;
    inorder($node->right, $out);
}

function maxDepth(?TreeNode $node): int
{
    return $node === null ? 0 : 1 + max(maxDepth($node->left), maxDepth($node->right));
}

function bstInsert(?TreeNode $node, int $val): TreeNode
{
    if ($node === null) return new TreeNode($val);
    if ($val < $node->val) $node->left = bstInsert($node->left, $val);
    else                    $node->right = bstInsert($node->right, $val);
    return $node;
}

// اعتبارسنجی BST: هر گره باید در بازه‌ی مجاز (min, max) باشد، نه فقط با فرزندانش مقایسه شود
function isValidBst(?TreeNode $node, ?int $min = null, ?int $max = null): bool
{
    if ($node === null) return true;
    if (($min !== null && $node->val <= $min) || ($max !== null && $node->val >= $max)) return false;
    return isValidBst($node->left, $min, $node->val) && isValidBst($node->right, $node->val, $max);
}

// Level-order با صف
function levelOrder(?TreeNode $root): array
{
    if ($root === null) return [];
    $levels = [];
    $q = new SplQueue();
    $q->enqueue($root);
    while (!$q->isEmpty()) {
        $level = [];
        for ($i = $q->count(); $i > 0; $i--) {      // اندازه‌ی سطح فعلی
            $node = $q->dequeue();
            $level[] = $node->val;
            if ($node->left)  $q->enqueue($node->left);
            if ($node->right) $q->enqueue($node->right);
        }
        $levels[] = $level;
    }
    return $levels;
}

function kthLargest(array $nums, int $k): int
{
    $heap = new SplMinHeap();
    foreach ($nums as $x) {
        $heap->insert($x);
        if ($heap->count() > $k) $heap->extract();   // کوچک‌ترین را دور بریز
    }
    return $heap->top();                              // کوچک‌ترینِ k تای بزرگ
}

BFS (Breadth-First Search)

پیمایش سطح‌به‌سطح با صف. در گراف بی‌وزن کوتاه‌ترین مسیر (کمترین تعداد یال) را پیدا می‌کند. O(V + E).

<?php
function shortestPathLength(array $graph, string $start, string $goal): int
{
    $dist = [$start => 0];
    $q = new SplQueue();
    $q->enqueue($start);
    while (!$q->isEmpty()) {
        $u = $q->dequeue();
        if ($u === $goal) return $dist[$u];
        foreach ($graph[$u] ?? [] as $v) {
            if (!isset($dist[$v])) {             // علامت‌گذاری هنگام enqueue، نه dequeue
                $dist[$v] = $dist[$u] + 1;
                $q->enqueue($v);
            }
        }
    }
    return -1;
}

DFS (Depth-First Search)

تا جای ممکن عمیق می‌رود و سپس برمی‌گردد؛ با بازگشت یا stack صریح. کاربرد: همبندی، شمارش مؤلفه‌ها، تشخیص دور، topological sort، backtracking. O(V + E).

<?php
// تعداد جزیره‌ها در شبکه‌ی '1' (خشکی) و '0' (آب) — O(rows × cols)
function numIslands(array $grid): int
{
    $rows = count($grid);
    $cols = $rows ? count($grid[0]) : 0;
    $count = 0;
    $sink = function (int $r, int $c) use (&$sink, &$grid, $rows, $cols): void {
        if ($r < 0 || $c < 0 || $r >= $rows || $c >= $cols || $grid[$r][$c] !== '1') return;
        $grid[$r][$c] = '0';                      // بازدیدشده
        $sink($r + 1, $c); $sink($r - 1, $c); $sink($r, $c + 1); $sink($r, $c - 1);
    };
    for ($r = 0; $r < $rows; $r++) {
        for ($c = 0; $c < $cols; $c++) {
            if ($grid[$r][$c] === '1') { $count++; $sink($r, $c); }
        }
    }
    return $count;
}

Dijkstra (کوتاه‌ترین مسیر با وزن نامنفی)

به‌صورت حریصانه، هر بار رأس با کمترین فاصله‌ی قطعی‌نشده را از priority queue برمی‌دارد و یال‌هایش را relax می‌کند. با binary heap: O((V + E) log V). با وزن منفی درست کار نمی‌کند (برای آن Bellman-Ford).

<?php
// $graph[$u] = [[$v, $weight], ...]
function dijkstra(array $graph, string $source): array
{
    $dist = [$source => 0];
    $pq = new SplPriorityQueue();               // max-heap → priority منفی برای رفتار min
    $pq->setExtractFlags(SplPriorityQueue::EXTR_BOTH);   // data و priority هر دو برگردند
    $pq->insert($source, 0);
    while (!$pq->isEmpty()) {
        ['data' => $u, 'priority' => $negD] = $pq->extract();
        if (-$negD > $dist[$u]) continue;          // ورودی کهنه (lazy deletion)
        foreach ($graph[$u] ?? [] as [$v, $w]) {
            $nd = $dist[$u] + $w;
            if (!isset($dist[$v]) || $nd < $dist[$v]) {
                $dist[$v] = $nd;
                $pq->insert($v, -$nd);
            }
        }
    }
    return $dist;
}

Topological Sort (Kahn)

ترتیب خطی رأس‌های یک DAG به‌طوری که برای هر یال u→v، u قبل از v بیاید. کاربرد: ترتیب اجرای migrationها/jobهای وابسته، build system، ترتیب پیش‌نیاز درس‌ها، resolve وابستگی پکیج‌ها (Composer). اگر همه‌ی رأس‌ها خروجی نشوند، گراف دور دارد.

<?php
// $deps = ['b' => ['a'], 'c' => ['a', 'b']]  یعنی b به a وابسته است (a → b)
function topoSort(array $nodes, array $deps): array
{
    $inDegree = array_fill_keys($nodes, 0);
    $adj = [];
    foreach ($deps as $node => $requires) {
        foreach ($requires as $req) {
            $adj[$req][] = $node;
            $inDegree[$node]++;
        }
    }
    $q = new SplQueue();
    foreach ($inDegree as $n => $d) if ($d === 0) $q->enqueue($n);

    $order = [];
    while (!$q->isEmpty()) {
        $u = $q->dequeue();
        $order[] = $u;
        foreach ($adj[$u] ?? [] as $v) {
            if (--$inDegree[$v] === 0) $q->enqueue($v);
        }
    }
    if (count($order) !== count($nodes)) {
        throw new RuntimeException('Cycle detected');
    }
    return $order;
}
// O(V + E)

Greedy و Dynamic Programming

Greedy (حریصانه)

در هر گام بهترین انتخاب محلی را انجام می‌دهد و هرگز به عقب برنمی‌گردد. فقط وقتی جواب بهینه می‌دهد که مسئله خاصیت greedy choice و optimal substructure داشته باشد؛ باید اثبات شود (معمولاً با استدلال exchange argument).

<?php
// Activity selection: بیشترین تعداد جلسه‌ی بدون تداخل — مرتب بر اساس زمان پایان
function maxMeetings(array $meetings): int     // [[start, end], ...]
{
    usort($meetings, fn ($a, $b) => $a[1] <=> $b[1]);
    $count = 0;
    $lastEnd = PHP_INT_MIN;
    foreach ($meetings as [$s, $e]) {
        if ($s >= $lastEnd) { $count++; $lastEnd = $e; }
    }
    return $count;
}

مثال نقض greedy: خرد کردن پول با سکه‌های {1, 3, 4} برای مبلغ ۶. greedy: 4+1+1 (سه سکه)؛ بهینه: 3+3 (دو سکه). برای سکه‌های دلخواه باید از DP استفاده کرد.

Dynamic Programming

DP برای مسائلی است که دو ویژگی دارند:

  • Overlapping subproblems: زیرمسئله‌های یکسان بارها حل می‌شوند.
  • Optimal substructure: جواب بهینه از جواب‌های بهینه‌ی زیرمسئله‌ها ساخته می‌شود.

گام‌ها: (۱) تعریف state (dp[i] یعنی چه؟)، (۲) رابطه‌ی بازگشتی (transition)، (۳) base case، (۴) ترتیب محاسبه، (۵) بهینه‌سازی حافظه در صورت امکان.

Memoization (Top-down)

  • بازگشت طبیعی + cache نتایج.
  • فقط زیرمسئله‌های لازم حل می‌شوند.
  • نوشتنش از روی رابطه‌ی بازگشتی ساده است.
  • هزینه‌ی call stack و خطر stack overflow در عمق زیاد.

Tabulation (Bottom-up)

  • پر کردن جدول از کوچک به بزرگ با حلقه.
  • بدون بازگشت؛ معمولاً سریع‌تر.
  • بهینه‌سازی حافظه آسان (نگه‌داشتن فقط چند سطر/مقدار آخر).
  • باید ترتیب درست محاسبه را بدانید؛ ممکن است زیرمسئله‌های غیرلازم را هم حل کند.
<?php
// فیبوناچی ساده: O(2ⁿ) — fib(n-2) بارها دوباره محاسبه می‌شود
function fibNaive(int $n): int { return $n < 2 ? $n : fibNaive($n - 1) + fibNaive($n - 2); }

// Memoization: O(n) زمان، O(n) حافظه
function fibMemo(int $n, array &$memo = []): int
{
    if ($n < 2) return $n;
    return $memo[$n] ??= fibMemo($n - 1, $memo) + fibMemo($n - 2, $memo);
}

// Tabulation با بهینه‌سازی حافظه: O(n) زمان، O(1) حافظه
function fib(int $n): int
{
    [$a, $b] = [0, 1];
    for ($i = 0; $i < $n; $i++) [$a, $b] = [$b, $a + $b];
    return $a;
}

// Climbing Stairs: به چند روش با گام‌های 1 یا 2 به پله‌ی n می‌رسیم؟
// dp[i] = dp[i-1] + dp[i-2]   (آخرین گام 1 بوده یا 2)
function climbStairs(int $n): int
{
    [$prev, $cur] = [1, 1];        // dp[0], dp[1]
    for ($i = 2; $i <= $n; $i++) [$prev, $cur] = [$cur, $prev + $cur];
    return $cur;
}

// Coin Change: کمترین تعداد سکه — O(amount × coins)
function coinChange(array $coins, int $amount): int
{
    $dp = array_fill(0, $amount + 1, PHP_INT_MAX);
    $dp[0] = 0;
    for ($x = 1; $x <= $amount; $x++) {
        foreach ($coins as $c) {
            if ($c <= $x && $dp[$x - $c] !== PHP_INT_MAX) {
                $dp[$x] = min($dp[$x], $dp[$x - $c] + 1);
            }
        }
    }
    return $dp[$amount] === PHP_INT_MAX ? -1 : $dp[$amount];
}

// Kadane: بیشترین مجموع زیرآرایه‌ی پیوسته — O(n)
function maxSubArray(array $a): int
{
    $best = $cur = $a[0];
    for ($i = 1, $n = count($a); $i < $n; $i++) {
        $cur = max($a[$i], $cur + $a[$i]);   // ادامه بده یا از نو شروع کن
        $best = max($best, $cur);
    }
    return $best;
}

0/1 Knapsack و LCS (ایده)

  • 0/1 Knapsack: n کالا با وزن w[i] و ارزش v[i]، ظرفیت W. state: dp[i][c] = بیشترین ارزش با i کالای اول و ظرفیت c. انتقال: dp[i][c] = max(dp[i-1][c], dp[i-1][c-w[i]] + v[i]) (برنداشتن یا برداشتن). زمان O(n·W)؛ حافظه با یک آرایه‌ی یک‌بعدی و پیمایش c از بزرگ به کوچک O(W).
  • LCS (طولانی‌ترین زیردنباله‌ی مشترک): dp[i][j] = LCS پیشوندهای a[0..i) و b[0..j). اگر a[i-1] == b[j-1] آنگاه dp[i-1][j-1] + 1، وگرنه max(dp[i-1][j], dp[i][j-1]). زمان و حافظه O(m·n). کاربرد: diff (مثل git diff)، مقایسه‌ی DNA. Edit Distance (Levenshtein) هم الگوی مشابهی دارد.
<?php
function lcs(string $a, string $b): int
{
    $m = strlen($a); $n = strlen($b);
    $dp = array_fill(0, $m + 1, array_fill(0, $n + 1, 0));
    for ($i = 1; $i <= $m; $i++) {
        for ($j = 1; $j <= $n; $j++) {
            $dp[$i][$j] = $a[$i - 1] === $b[$j - 1]
                ? $dp[$i - 1][$j - 1] + 1
                : max($dp[$i - 1][$j], $dp[$i][$j - 1]);
        }
    }
    return $dp[$m][$n];
}
// lcs("ABCBDAB", "BDCABA") = 4

تفاوت DP و Divide & Conquer: هر دو مسئله را به زیرمسئله می‌شکنند، ولی در Divide & Conquer (مثل merge sort) زیرمسئله‌ها مستقلاند و تکرار نمی‌شوند؛ در DP هم‌پوشاناند و ذخیره‌ی نتایج سود دارد. تفاوت DP و Greedy: greedy یک انتخاب را بدون بررسی بقیه قطعی می‌کند؛ DP همه‌ی انتخاب‌ها را (به‌صورت کارآمد) بررسی می‌کند.

سوالات تشریحی

Two Sum: آرایه‌ای از اعداد صحیح و عدد target داده شده است. اندیس دو عددی را که مجموعشان target است برگردانید. راه‌حل بهینه و پیچیدگی آن را توضیح دهید.

Brute force: بررسی همه‌ی جفت‌ها با دو حلقه ⇒ O(n²) زمان، O(1) حافظه.

ایده‌ی بهینه: برای هر عدد x، «مکمل» آن target - x است. با یک hash map از مقادیر دیده‌شده به اندیسشان، وجود مکمل را در O(1) چک می‌کنیم. یک گذر کافی است.

<?php
function twoSum(array $nums, int $target): ?array
{
    $seen = [];                                   // value => index
    foreach ($nums as $i => $x) {
        $need = $target - $x;
        if (array_key_exists($need, $seen)) {
            return [$seen[$need], $i];
        }
        $seen[$x] = $i;                           // بعد از چک، تا یک عنصر با خودش جفت نشود
    }
    return null;
}
// twoSum([2, 7, 11, 15], 9) → [0, 1]

پیچیدگی: زمان O(n)، حافظه O(n) — معاوضه‌ی کلاسیک حافظه با زمان.

حالت‌های مرزی: عدد تکراری ([3,3]، target 6) درست کار می‌کند چون قبل از درج چک می‌کنیم؛ نبود جواب ⇒ null.

نسخه‌ی مرتب: اگر آرایه مرتب باشد، two pointers با O(1) حافظه. اگر مرتب نیست و اندیس اصلی لازم است، sort + two pointers ⇒ O(n log n).

Valid Parentheses: تابعی بنویسید که بررسی کند رشته‌ای از ()[]{} به‌درستی باز و بسته شده است.

ایده: آخرین پرانتز باز باید اولین پرانتزی باشد که بسته می‌شود ⇒ LIFO ⇒ Stack. پرانتز باز را push می‌کنیم؛ با دیدن پرانتز بسته، بالای stack باید جفت متناظرش باشد.

<?php
function isValid(string $s): bool
{
    $pairs = [')' => '(', ']' => '[', '}' => '{'];
    $stack = [];
    for ($i = 0, $n = strlen($s); $i < $n; $i++) {
        $ch = $s[$i];
        if (isset($pairs[$ch])) {                       // بسته
            if (array_pop($stack) !== $pairs[$ch]) {   // stack خالی ⇒ null ⇒ false
                return false;
            }
        } else {
            $stack[] = $ch;                             // باز
        }
    }
    return $stack === [];                               // باز بسته‌نشده نماند
}
// "([]{})" → true ، "(]" → false ، "((" → false ، "" → true

پیچیدگی: زمان O(n)، حافظه O(n) در بدترین حالت (همه باز).

حالت‌های مرزی: رشته‌ی خالی، شروع با پرانتز بسته، پرانتزهای باز باقی‌مانده در انتها، طول فرد (می‌توان زود false برگرداند).

کاربرد واقعی: parserها، اعتبارسنجی template، تطبیق تگ‌های HTML/XML، ارزیابی عبارات ریاضی.

یک linked list یک‌طرفه را معکوس کنید (هم به روش تکراری و هم بازگشتی) و پیچیدگی هر کدام را بیان کنید.

ایده: جهت هر اشاره‌گر next را برعکس کنیم. سه اشاره‌گر لازم است: prev، current و next (برای اینکه ادامه‌ی لیست گم نشود).

<?php
// تکراری — O(n) زمان، O(1) حافظه
function reverseList(?ListNode $head): ?ListNode
{
    $prev = null;
    $cur = $head;
    while ($cur !== null) {
        $next = $cur->next;      // ۱. نگه‌داشتن ادامه
        $cur->next = $prev;      // ۲. برعکس کردن اشاره‌گر
        $prev = $cur;            // ۳. جلو رفتن
        $cur = $next;
    }
    return $prev;                // سر جدید
}

// بازگشتی — O(n) زمان، O(n) حافظه (call stack)
function reverseRecursive(?ListNode $head): ?ListNode
{
    if ($head === null || $head->next === null) return $head;
    $newHead = reverseRecursive($head->next);
    $head->next->next = $head;   // گره بعدی به من اشاره کند
    $head->next = null;
    return $newHead;
}

Dry run: 1→2→3: بعد از گام اول 1→null، prev=1؛ بعد 2→1؛ بعد 3→2→1.

مقایسه: نسخه‌ی تکراری برای لیست‌های بلند امن‌تر است (بدون خطر stack overflow). حالت‌های مرزی: لیست خالی و تک‌گره.

کد زیر برای پیدا کردن عناصر تکراری نوشته شده است. چه مشکلی دارد و چگونه بهینه‌اش می‌کنید؟ 
<?php
function findDuplicates(array $items): array
{
    $seen = [];
    $dups = [];
    foreach ($items as $item) {
        if (in_array($item, $seen)) {
            if (!in_array($item, $dups)) $dups[] = $item;
        } else {
            $seen[] = $item;
        }
    }
    return $dups;
}

مشکل کارایی: in_array جست‌وجوی خطی O(n) است و درون حلقه‌ای با n تکرار قرار دارد ⇒ کل الگوریتم O(n²). برای ۱۰۰٬۰۰۰ عنصر، حدود ۱۰¹⁰ مقایسه در بدترین حالت.

مشکل صحت: in_array بدون پارامتر سوم مقایسه‌ی loose (==) انجام می‌دهد؛ مثلاً "1" و 1 یا "abc" و 0 (در PHP 7) ممکن است برابر تلقی شوند. اگر می‌ماند، باید in_array($x, $arr, true) باشد.

<?php
function findDuplicates(array $items): array
{
    $seen = [];

    foreach ($items as $item) {
        if (isset($seen[$item])) {
            $dups[$item] = true;                // set برای جلوگیری از تکرار در خروجی

            $seen[$item] = true;
        }
    }

// O(n) زمان، O(n) حافظه

نکته: این روش برای int/string کار می‌کند (کلیدهای آرایه)؛ کلیدهای رشته‌ای عددی به int تبدیل می‌شوند. برای اشیا از spl_object_id یا SplObjectStorage استفاده کنید. اگر فقط «آیا تکراری هست؟» مطرح است: count($a) !== count(array_flip($a)) یا خروج زودهنگام در اولین تکرار. جایگزین بدون حافظه‌ی اضافه: sort + مقایسه‌ی همسایه‌ها ⇒ O(n log n).

طول طولانی‌ترین زیررشته‌ی بدون کاراکتر تکراری را پیدا کنید (مثلاً برای "abcabcbb" جواب ۳ است).

Brute force: بررسی همه‌ی زیررشته‌ها و یکتایی هر کدام ⇒ O(n³) یا با set O(n²).

ایده (Sliding Window): پنجره‌ی [left, right] همیشه بدون تکرار است. right را جلو می‌بریم؛ اگر کاراکتر جدید قبلاً درون پنجره دیده شده، left را به بعد از آخرین وقوعش می‌پریم. آخرین اندیس هر کاراکتر را در hash map نگه می‌داریم.

<?php
function lengthOfLongestSubstring(string $s): int
{
    $last = [];          // char => آخرین اندیس
    $left = 0;
    $best = 0;
    for ($right = 0, $n = strlen($s); $right < $n; $right++) {
        $ch = $s[$right];
        if (isset($last[$ch]) && $last[$ch] >= $left) {
            $left = $last[$ch] + 1;            // پرش از روی تکراری
        }
        $last[$ch] = $right;
        $best = max($best, $right - $left + 1);
    }
    return $best;
}
// "abcabcbb" → 3 ("abc") ، "bbbbb" → 1 ، "pwwkew" → 3 ("wke") ، "" → 0

نکته‌ی ظریف: شرط $last[$ch] >= $left لازم است؛ وگرنه وقوع قدیمی خارج از پنجره باعث می‌شود left به عقب برگردد (مثال "abba").

پیچیدگی: زمان O(n) (هر کاراکتر یک بار)، حافظه O(min(n, |alphabet|)).

UTF-8: برای متن فارسی ابتدا mb_str_split($s) و روی آرایه‌ی کاراکترها کار کنید، چون $s[$i] بایت است.

Merge Intervals: لیستی از بازه‌ها داده شده است؛ بازه‌های هم‌پوشان را ادغام کنید. مثال: [[1,3],[2,6],[8,10],[15,18]] ← [[1,6],[8,10],[15,18]]

ایده: اگر بازه‌ها بر اساس شروع مرتب باشند، هر بازه فقط ممکن است با آخرین بازه‌ی ادغام‌شده هم‌پوشانی داشته باشد. پس: sort، سپس یک گذر.

<?php
function mergeIntervals(array $intervals): array
{
    if ($intervals === []) return [];
    usort($intervals, fn ($a, $b) => $a[0] <=> $b[0]);
    $merged = [$intervals[0]];
    for ($i = 1, $n = count($intervals); $i < $n; $i++) {
        [$start, $end] = $intervals[$i];
        $last = &$merged[count($merged) - 1];
        if ($start <= $last[1]) {                 // هم‌پوشانی (یا مماس)
            $last[1] = max($last[1], $end);         // max: بازه‌ی [1,10] و [2,3]
        } else {
            $merged[] = [$start, $end];
        }
        unset($last);                               // شکستن reference
    }
    return $merged;
}

پیچیدگی: O(n log n) برای sort + O(n) گذر ⇒ O(n log n)؛ حافظه O(n) برای خروجی.

حالت‌های مرزی: بازه‌ی کاملاً درون بازه‌ی دیگر (به همین دلیل max)، بازه‌های مماس ([1,4],[4,5] — بسته به تعریف مسئله ادغام شوند یا نه)، لیست خالی یا تک‌عضوی.

کاربرد واقعی: ادغام بازه‌های رزرو، شیفت‌های کاری، ساعات در دسترس بودن، بازه‌های IP.

در یک آرایه‌ی مرتب که ممکن است عناصر تکراری داشته باشد، اولین و آخرین موقعیت یک عدد را در O(log n) پیدا کنید.

ایده: binary search معمولی در اولین برخورد متوقف می‌شود؛ ما به مرز نیاز داریم. دو بار lower bound:

  • اولین موقعیت = اولین اندیسی که a[i] >= x.
  • آخرین موقعیت = (اولین اندیسی که a[i] >= x + 1) منهای ۱ — یا upper bound با شرط a[i] > x.
<?php
function lowerBound(array $a, int $x): int
{
    $lo = 0; $hi = count($a);            // [lo, hi)
    while ($lo < $hi) {
        $mid = $lo + intdiv($hi - $lo, 2);
        if ($a[$mid] < $x) $lo = $mid + 1;
        else $hi = $mid;
    }
    return $lo;
}

function searchRange(array $a, int $x): array
{
    $first = lowerBound($a, $x);
    if ($first === count($a) || $a[$first] !== $x) return [-1, -1];
    $last = lowerBound($a, $x + 1) - 1;
    return [$first, $last];
}
// searchRange([5,7,7,8,8,10], 8) → [3, 4]

پیچیدگی: دو binary search ⇒ O(log n) زمان، O(1) حافظه. تعداد وقوع هم last - first + 1 است.

چرا راه ساده‌تر بد است؟ پیدا کردن یک وقوع و سپس گسترش خطی به چپ و راست در بدترین حالت (همه‌ی عناصر برابر x) O(n) می‌شود.

اشکالات رایج: قرارداد بازه‌ی نیم‌باز را رعایت کنید؛ hi = mid (نه mid - 1) و شرط حلقه lo < hi.

function reverseString(string $s): string
{

    }
    return $s;
}

Group Anagrams: کلماتی را که آناگرام یکدیگرند گروه‌بندی کنید. مثال: ["eat","tea","tan","ate","nat","bat"].

تعریف: دو کلمه آناگرام‌اند اگر حروف یکسان با تعداد یکسان داشته باشند. پس به یک کلید canonical نیاز داریم که برای همه‌ی آناگرام‌ها یکسان باشد و آن را کلید hash map قرار دهیم.

روش ۱ — حروف مرتب‌شده به‌عنوان کلید:

<?php
function groupAnagrams(array $words): array
{
    $groups = [];
    foreach ($words as $w) {
        $chars = str_split($w);
        sort($chars);
        $groups[implode('', $chars)][] = $w;      // "aet" => [eat, tea, ate]
    }
    return array_values($groups);
}
// → [["eat","tea","ate"], ["tan","nat"], ["bat"]]

پیچیدگی: n کلمه با طول حداکثر k ⇒ O(n · k log k) زمان، O(n · k) حافظه.

Missing Number: آرایه‌ای شامل n عدد متمایز از بازه‌ی 0 تا n داده شده است. عدد گمشده را با حافظه‌ی O(1) پیدا کنید.

روش‌ها:

  • Sort: O(n log n) — کند.
  • Hash set: O(n) زمان ولی O(n) حافظه.
  • فرمول جمع گاوس: مجموع 0..n برابر n(n+1)/2؛ اختلاف با مجموع آرایه همان عدد گمشده است. O(n) زمان، O(1) حافظه.
  • XOR: چون x ^ x = 0 و x ^ 0 = x، XOR همه‌ی اندیس‌ها و همه‌ی مقادیر، فقط عدد گمشده را باقی می‌گذارد. بدون خطر overflow.
<?php
function missingNumberSum(array $nums): int
{
    $n = count($nums);
    return intdiv($n * ($n + 1), 2) - array_sum($nums);
}

function missingNumberXor(array $nums): int
{
    $x = count($nums);                    // n
    foreach ($nums as $i => $v) {
        $x ^= $i ^ $v;
    }
    return $x;
}
// [3, 0, 1] → 2 ، [0, 1] → 2 ، [1] → 0

Trade-off: روش جمع ساده و خواناست، اما در زبان‌هایی با int محدود برای n بزرگ ممکن است overflow کند (در PHP روی پلتفرم ۶۴ بیتی، int 64 بیتی است و در صورت overflow به float تبدیل می‌شود که دقت را از دست می‌دهد). روش XOR این مشکل را ندارد.

تعمیم: اگر دو عدد گمشده باشد، از ترکیب مجموع و مجموع مربعات یا تقسیم بر اساس یک بیت XOR استفاده می‌شود.

Amortized Complexity چیست؟ با مثال آرایه‌ی پویا توضیح دهید که چرا append به‌طور amortized O(1) است.

تعریف: تحلیل amortized هزینه‌ی میانگین هر عملیات در بدترین دنباله‌ی ممکن از عملیات‌ها را می‌دهد. برخلاف average-case، به توزیع احتمالی ورودی وابسته نیست؛ تضمین می‌کند که مجموع هزینه‌ی m عملیات حداکثر m برابر هزینه‌ی amortized است، حتی اگر برخی عملیات‌ها تکی گران باشند.

مثال آرایه‌ی پویا: آرایه با ظرفیت c؛ append وقتی جا هست O(1) است. وقتی پر شد، آرایه‌ای با ظرفیت 2c ساخته و همه‌ی عناصر کپی می‌شوند (O(n)).

  • برای n بار append از ظرفیت ۱، کپی‌ها در اندازه‌های 1، 2، 4، …، n رخ می‌دهند.
  • مجموع کپی‌ها: 1 + 2 + 4 + … + n < 2n.
  • کل هزینه: n (درج‌ها) + 2n (کپی‌ها) = O(n) ⇒ هر append به‌طور amortized O(1).

چرا دو برابر و نه +۱۰؟ با رشد ثابت (هر بار ۱۰ خانه)، تعداد resizeها n/10 و مجموع کپی‌ها O(n²) می‌شود ⇒ amortized O(n). رشد هندسی کلید است.

مثال‌های دیگر: rehash در hash table (آرایه‌ی PHP هم هنگام پر شدن بزرگ می‌شود)، صف با دو stack، union-find. در عمل: بیشتر $arr[] = $xها ارزان‌اند ولی گاهی یکی کند است؛ برای سیستم‌های real-time این spike مهم است.

Hash Table چگونه کار می‌کند؟ روش‌های رسیدگی به برخورد (collision) را توضیح دهید و بگویید چرا بدترین حالت O(n) است.

سازوکار: تابع hash کلید را به یک عدد تبدیل می‌کند و hash(key) mod capacity اندیس bucket را می‌دهد. با تابع hash خوب و load factor کنترل‌شده، درج/جست‌وجو/حذف به‌طور میانگین O(1) است.

Collision: چون فضای کلیدها از تعداد bucketها بزرگ‌تر است، دو کلید متفاوت ممکن است به یک bucket برسند (اصل لانه‌ی کبوتری).

  • Separate Chaining: هر bucket یک لیست پیوندی (یا در برخی پیاده‌سازی‌ها درخت متوازن) از جفت‌ها دارد. ساده، حذف آسان، تحمل load factor بالا. هزینه: اشاره‌گرها و cache locality ضعیف‌تر.
  • Open Addressing: همه چیز در خود آرایه است؛ در برخورد خانه‌ی بعدی بررسی می‌شود: Linear probing (i+1، i+2…؛ cache-friendly ولی دچار clustering)، Quadratic probing (i+1²، i+2²…)، Double hashing (گام با hash دوم). حذف نیاز به tombstone دارد و با load factor بالا به‌سرعت کند می‌شود.

Load factor و resize: وقتی n / capacity از آستانه گذشت، ظرفیت (معمولاً دو برابر) و همه‌ی کلیدها rehash می‌شوند: O(n) تکی، amortized O(1).

بدترین حالت O(n): اگر همه‌ی کلیدها در یک bucket بیفتند (تابع hash بد یا حمله‌ی عمدی hash flooding)، جست‌وجو به پیمایش خطی تبدیل می‌شود. دفاع: hash تصادفی با seed، محدود کردن تعداد ورودی‌ها (مثل max_input_vars در PHP)، یا تبدیل chain بلند به درخت.

در PHP: array یک hash table مرتب با chaining است که ترتیب درج را هم حفظ می‌کند.

سناریو: از یک فایل لاگ با ۵۰ میلیون خط، ۱۰ آدرس IP پرتکرار را پیدا کنید. رویکرد و پیچیدگی را توضیح دهید.

گام ۱ — شمارش: فایل را جریانی (streaming) و خط‌به‌خط بخوانید (نه file() که کل فایل را در حافظه می‌برد) و فراوانی هر IP را در hash map بشمارید: O(N) زمان، O(U) حافظه (U = تعداد IP یکتا).

گام ۲ — انتخاب top-k: به جای مرتب‌سازی کامل (O(U log U))، یک min-heap با اندازه‌ی k=10: هر IP را درج کن و اگر اندازه از k گذشت، کوچک‌ترین را حذف کن ⇒ O(U log k).

<?php
function topIps(string $path, int $k = 10): array
{
    $counts = [];
    $fh = fopen($path, 'rb');
    while (($line = fgets($fh)) !== false) {
        $ip = strtok($line, ' ');                 // فرض: IP اولین فیلد است
        $counts[$ip] = ($counts[$ip] ?? 0) + 1;
    }
    fclose($fh);

    $heap = new SplMinHeap();                     // عناصر: [count, ip]
    foreach ($counts as $ip => $c) {
        $heap->insert([$c, (string) $ip]);
        if ($heap->count() > $k) $heap->extract();
    }
    $result = [];
    foreach ($heap as [$c, $ip]) $result[$ip] = $c;
    arsort($result);
    return $result;
}

اگر IPهای یکتا در حافظه جا نشوند: partition بر اساس hash(ip) mod P به P فایل کوچک‌تر (همه‌ی وقوع‌های یک IP در یک فایل)، top-k هر فایل، سپس ادغام نتایج. یا الگوریتم‌های تقریبی مثل Count-Min Sketch. در دنیای واقعی: sort | uniq -c | sort -rn | head یا ابزارهایی مثل ELK/ClickHouse.

پیچیدگی کل: O(N + U log k) زمان، O(U + k) حافظه.

Memoization و Tabulation را در Dynamic Programming مقایسه کنید و مسئله‌ی Climbing Stairs را با هر دو روش حل کنید.

مسئله: به چند روش می‌توان با گام‌های ۱ یا ۲ از پله‌ی ۰ به پله‌ی n رسید؟ آخرین گام یا از n-1 بوده یا از n-2 ⇒ ways(n) = ways(n-1) + ways(n-2)، با ways(0) = ways(1) = 1. (همان فیبوناچی.)

<?php
// Top-down (Memoization)
function climbMemo(int $n, array &$memo = []): int
{
    if ($n <= 1) return 1;
    return $memo[$n] ??= climbMemo($n - 1, $memo) + climbMemo($n - 2, $memo);
}

// Bottom-up (Tabulation) با حافظه‌ی O(1)
function climbTab(int $n): int
{
    $a = 1; $b = 1;                 // ways(0), ways(1)
    for ($i = 2; $i <= $n; $i++) {
        [$a, $b] = [$b, $a + $b];
    }
    return $b;
}

BFS و DFS را مقایسه کنید. برای پیدا کردن «کمترین تعداد واسطه بین دو کاربر در شبکه‌ی اجتماعی» کدام را انتخاب می‌کنید و چرا؟

BFS: پیمایش سطح‌به‌سطح با صف؛ ابتدا همه‌ی رأس‌های با فاصله‌ی ۱، سپس ۲ و… . DFS: تا انتهای یک مسیر عمیق می‌رود و سپس backtrack می‌کند؛ با stack یا بازگشت. هر دو O(V + E) زمان دارند.

  • حافظه: BFS به اندازه‌ی پهن‌ترین سطح (در شبکه‌ی اجتماعی می‌تواند بسیار بزرگ باشد)؛ DFS به اندازه‌ی عمق.
  • کوتاه‌ترین مسیر بی‌وزن: فقط BFS تضمین می‌کند اولین باری که به مقصد می‌رسد، با کمترین تعداد یال است.
  • کاربرد DFS: تشخیص دور، topological sort، مؤلفه‌های همبند، پیدا کردن همه‌ی مسیرها، backtracking (sudoku، جایگشت‌ها).

پاسخ سناریو: BFS، چون «کمترین تعداد واسطه» همان کوتاه‌ترین مسیر در گراف بی‌وزن است. بهبودها:

  • Bidirectional BFS: هم‌زمان از هر دو کاربر جست‌وجو و توقف در محل برخورد؛ تعداد رأس‌های بازدیدشده به‌شدت کم می‌شود (حدوداً از b^d به 2·b^(d/2)).
  • محدود کردن عمق (مثلاً حداکثر ۳ واسطه) و علامت‌گذاری بازدیدشده‌ها هنگام enqueue.
  • در مقیاس واقعی از graph database یا پیش‌محاسبه استفاده می‌شود.

اگر یال‌ها وزن داشتند (مثلاً میزان صمیمیت)، Dijkstra لازم بود.

کد binary search زیر گاهی در حلقه‌ی بی‌نهایت گیر می‌کند یا جواب غلط می‌دهد. مشکلاتش را پیدا کنید. 
<?php
function search(array $a, int $target): int
{
    $lo = 0;
    $hi = count($a);
    while ($lo < $hi) {
        $mid = ($lo + $hi) / 2;
        if ($a[$mid] == $target) return $mid;
        if ($a[$mid] < $target) $lo = $mid;
        else $hi = $mid - 1;
    }
    return -1;
}

مشکلات:

  1. ($lo + $hi) / 2 در PHP عدد float برمی‌گرداند (مثلاً 2.5)؛ استفاده از float به‌عنوان اندیس آرایه منسوخ است و به int بریده می‌شود. باید intdiv یا >> 1 استفاده شود. در زبان‌های با int محدود، lo + hi ممکن است overflow کند ⇒ lo + (hi - lo) / 2.
  2. $lo = $mid: وقتی hi = lo + 1، mid برابر lo می‌شود و lo هرگز جلو نمی‌رود ⇒ حلقه‌ی بی‌نهایت. باید $lo = $mid + 1 باشد، چون mid قبلاً بررسی شده است.
  3. ناسازگاری قرارداد بازه: hi اولیه count($a) (نیم‌باز) و شرط lo < hi است، ولی $hi = $mid - 1 مربوط به بازه‌ی بسته است و ممکن است عنصر mid - 1 را از دست بدهد. در بازه‌ی نیم‌باز باید $hi = $mid باشد.
  4. == به جای ===: مقایسه‌ی loose.
<?php
function search(array $a, int $target): int
{
    $lo = 0;
    $hi = count($a);                         // [lo, hi)
    while ($lo < $hi) {
        $mid = $lo + intdiv($hi - $lo, 2);
        if ($a[$mid] === $target) return $mid;
        if ($a[$mid] < $target) $lo = $mid + 1;
        else $hi = $mid;
    }
    return -1;
}

Topological Sort چیست؟ یک کاربرد آن در توسعه‌ی backend مثال بزنید و الگوریتم Kahn را توضیح دهید.

تعریف: ترتیب خطی رأس‌های یک گراف جهت‌دار بدون دور (DAG) به‌طوری که برای هر یال u → v، u قبل از v بیاید. فقط برای DAG وجود دارد و ممکن است یکتا نباشد.

کاربردها در backend: ترتیب اجرای jobهای وابسته در یک pipeline (Laravel Bus chain/batch یا DAG در Airflow)، ترتیب ایجاد جداول بر اساس FK در seeding یا migration، resolve وابستگی پکیج‌ها (Composer)، ترتیب boot شدن service providerها یا microserviceها، build system.

الگوریتم Kahn:

  1. درجه‌ی ورودی (in-degree) هر رأس را حساب کن.
  2. همه‌ی رأس‌های با in-degree صفر (بدون پیش‌نیاز) را در صف بگذار.
  3. تا صف خالی نشده: رأسی را خارج و به خروجی اضافه کن؛ in-degree همسایه‌هایش را یکی کم کن و هر کدام صفر شد را وارد صف کن.
  4. اگر تعداد رأس‌های خروجی کمتر از V بود ⇒ گراف دور دارد (وابستگی حلقوی) و ترتیب ممکن نیست.

  └──► products ────────┘

پیچیدگی: O(V + E) زمان و حافظه.

روش جایگزین: DFS و افزودن رأس به ابتدای لیست بعد از اتمام بازدید همه‌ی فرزندانش (post-order معکوس)؛ تشخیص دور با سه رنگ (سفید/خاکستری/سیاه). مزیت Kahn: تشخیص دور طبیعی و امکان پردازش موازی رأس‌های هم‌سطح.

  • PHP: isset O(1)، in_array O(n)، array_shift O(n)، sort O(n log n) و stable (8.0+).

Hash

  • میانگین O(1)، بدترین O(n).
  • Collision: chaining یا open addressing (linear/quadratic/double hashing).
  • Load factor ← resize و rehash.
  • Set در PHP: $s[$x] = true + isset.

الگوها

  • Two pointers: آرایه‌ی مرتب، پالیندروم، حذف تکراری درجا.
  • Sliding window: زیرآرایه/زیررشته‌ی پیوسته؛ اعداد نامنفی.
  • Prefix sum: جمع بازه O(1)؛ با hash map برای «تعداد زیرآرایه با مجموع k».
  • Monotonic stack: «بزرگ‌تر بعدی» O(n).
  • Fast/slow: وسط لیست، تشخیص حلقه (Floyd).
  • Binary search on answer: شرط یکنوا روی جواب.

Binary Search

  • mid = lo + intdiv(hi - lo, 2)
  • بسته: lo <= hi، hi = mid - 1.
  • نیم‌باز: lo < hi، hi = mid.
  • همیشه lo = mid + 1.

مرتب‌سازی

  • Stable: bubble، insertion، merge، counting.
  • Unstable: selection، quick، heap.
  • Merge: n log n تضمینی، O(n) حافظه.
  • Quick: میانگین n log n، بدترین n²، O(log n) حافظه، pivot تصادفی.
  • Heap: n log n تضمینی، O(1) حافظه.
  • Insertion: داده‌ی تقریباً مرتب و n کوچک.
  • Counting: O(n + k) برای بازه‌ی کوچک.
  • کران پایین مقایسه‌ای: Ω(n log n).

درخت و Heap

  • BST: متوازن O(log n)، نامتوازن O(n).
  • In-order روی BST = مرتب.
  • Pre: کپی؛ Post: حذف/محاسبه از پایین؛ Level: صف.
  • Validate BST: بازه‌ی (min, max).
  • Heap: peek O(1)، insert/extract O(log n)، heapify O(n).
  • Top-k: min-heap اندازه‌ی k ⇒ O(n log k).
  • PHP: SplMinHeap، SplMaxHeap، SplPriorityQueue (max).

گراف

  • Adjacency list O(V+E)؛ matrix O(V²).
  • BFS: صف، کوتاه‌ترین مسیر بی‌وزن، علامت هنگام enqueue.
  • DFS: stack/بازگشت، دور، مؤلفه‌ها، backtracking.
  • Dijkstra: وزن نامنفی، O((V+E) log V)، lazy deletion.
  • Topological (Kahn): in-degree صفر در صف؛ کمتر از V خروجی = دور.

Greedy و DP

  • Greedy: انتخاب محلی بهینه؛ باید اثبات شود (activity selection: مرتب بر اساس پایان).
  • DP: زیرمسئله‌ی هم‌پوشان + زیرساختار بهینه.
  • State ← transition ← base case ← ترتیب ← بهینه‌سازی حافظه.
  • Memo (top-down) در برابر tabulation (bottom-up).
  • Fib/Stairs: O(n)، حافظه O(1).
  • Coin change: O(amount × coins).
  • Knapsack 0/1: O(n·W). LCS: O(m·n).
  • Kadane: cur = max(x, cur + x).
